# 豆包自动签到（macOS）

每天自动领掉豆包 PC 端「天天领额度」的 **200 活动额度**，你什么都不用做。

装好之后，它每天在你不用电脑的时候，悄悄跑几十秒就退出——**不是常驻程序**，不占内存、不占进程、不在菜单栏留图标。

**目前只支持 macOS。** 定时用 launchd，下一步计划支持 Windows。

**适合谁**：一台基本不休眠的 Mac，尤其 Mac mini / iMac 这类常年开机的主机。笔记本也能用，只是合盖期间不会跑。

| 它会做的事 | 它不会做的事 |
|---|---|
| 到点打开签到页，点一下「立即签到」 | 见[已知限制](#已知限制) |
| 今天已经签过就直接跳过，连客户端都不碰 | 不会在不用签到时还碰客户端 |
| 用完把豆包还原成原来的状态，不留调试端口 | 不会一直挂在后台 不会替你完成其他任务 |
| 只在出问题时弹窗，成功时一声不响 | 不会在正常运行时打扰到你 |
| 脚本用的是客户端自己的登录态 | 不读也不存你的登录凭证 |

---

## 它对你的电脑做了什么（如实说明）

1. **会重启一次豆包客户端**（在有需要时）：为了短暂打开一个带本地调试端口的豆包客户端，而调试端口只能带参数启动应用程序。脚本会先判断忙闲、尽量挑你不用豆包客户端的时候、用完会帮你还原到之前状态。
2. **会短暂开一个本地调试端口**（9225 起）：这个端口**没有鉴权**，本机其他程序理论上能借它读到你的登录态——所以脚本用完立刻关闭，任何情况下都不会留着。
3. **只读写项目目录**：此外只会读取豆包客户端的 `Info.plist`（为了记录版本号）。不读聊天记录、不读凭证文件。
4. 定时任务装在 `~/Library/LaunchAgents/com.xmyfun.doubao-checkin.plist`，卸载即删。

## 已知限制

- **只做「每日签到」这一个动作。** 豆包「任务体系」里另外 7 个任务是让你去跑 AI 任务（生成 PPT、操作文件、建定时任务），点一下会真的消耗额度去执行，所以本项目**不做**——想拿那份额度得自己去点
- 关机、睡眠期间、停在登录界面、注销时不跑（launchd 的 agent 只在 macOS 用户登录后运行），但会在 macOS 用户登录后立即补跑
- 整天不开机的那天会漏签，额度当天有效、补不回来
- 活动是阶段性的，官方随时可能下线；页面改版也会让它失效（届时 `UNKNOWN`）

只列**真机跑过并留下运行记录**的版本。

| 豆包客户端 | 结果 | 说明 |
|---|---|---|
| **2.34.6** | 通过 | 2026-11-01：完整签到成功 1 次 |
| **2.33.5** | 通过 | 2026-10-25 ~ 10-30：完整签到成功 2 次 |

## 技术栈

| 部分 | 用了什么 |
|---|---|
| 运行环境 | **Node 22+，零第三方依赖**——`npm install` 之后不会出现 `node_modules`。HTTP 用内置 `fetch`、CDP 用内置 `WebSocket`、测试用 `node:test` |
| 定时 | **launchd**：`StartCalendarInterval` 定点触发、`StartInterval` 兜底、`RunAtLoad` 登录后补跑 |
| 操作客户端 | **CDP**（Chrome DevTools Protocol）开调试端口读页面、点按钮；不开端口时用 **AppleScript + Unix 信号**让它退出 |
| 忙闲判断 | `ps` / `lsof` / `nettop` 只读采样，算 CPU 与网入的中位数 |
| 入口 | **bash**，负责在"还没有 node"的时候把 node 找出来 |

**node 装在哪儿不用管**：脚本自己找，顺序是「config.conf 指定 → 项目自带 → PATH → Homebrew → nvm 等版本管理器 → 豆包自带 → 其他软件自带」，前一个能用就不看后面的。豆包自带的那份通常就够。

## 快速开始

先把项目放到本地（位置先不用纠结——第 2 步会讲脚本位置的注意事项）：

```bash
cd ~/Library/Application Support/
git clone https://github.com/xmyfun/doubao-checkin.git
cd doubao-checkin
```

### 第 0 步：确认豆包客户端已登录

打开豆包看一眼，确认已经登录。

### 第 1 步：手动签一次，确认这台机器能跑通

如果想自己调端口、日志位置、是否允许重启豆包、忙闲阈值，就把 `config.conf.template` 改名成 `config.conf` 再编辑。不改也行——**首次运行会自动生成一份**默认配置，绝大多数人都够用。

先用 --dry-run 模式进行测试，或者直接运行脚本尝试签到：

```bash
./scripts/doubao-checkin.sh --dry-run
./scripts/doubao-checkin.sh
```

看到 `[SUCCESS]` 或 `[ALREADY]` 就是通了。

> 它可能会重启一次豆包——**这一步没法避免**：调试端口只能在启动时带参数打开，客户端没有"启用调试"这个开关。
> 如果你在运行脚本前已经打开了豆包客户端，一次完整签到流程会持续 30 秒以上，因为脚本要观察足够时间来确定你的豆包客户端是否正在执行任务。

### 第 2 步：安装自动签到的定时任务

**首先务必确认脚本文件夹位置**，因为定时任务的 plist 文件记录的是自动签到脚本的绝对路径。

**不能**放在 `~/Documents`、`~/Desktop`、`~/Downloads` 等特殊文件夹中，原因是 macOS 的 TCC：后台进程读这三个目录会被拒绝，而 launchd 只把错误写进 `.err` 文件——**静默失败，你永远不知道它挂了**。

请将项目文件夹放在除上述文件夹以外的普通目录（`~/doubao-checkin`、`~/Projects/doubao-checkin`），推荐 `~/Library/Application Support/doubao-checkin`。

然后运行下面的脚本来安装 Launch Agent 服务。

```bash
./scripts/install-launchd.sh
```

> **注意：定时脚本安装后会立刻真跑一次签到。** plist 里带 `RunAtLoad`，launchd 的语义是"任务加载时执行一次"，
> 所以，如果安装定时脚本的那一刻豆包客户端正开着、而且今天还没签到，那么不要惊讶，它可能会被重启一次。且签到前的忙闲时判断会持续30秒以上。

安装 Launch Agent 服务之后，默认每天会跑这几次，都能在 `config.conf` 的 `schedule.*` 里改：

| 时刻 | 作用 |
|---|---|
| **03:33** | 主跑（凌晨几乎没人用电脑） |
| **13:33** | 兜底（凌晨机器睡了，醒来后补上） |
| 登录/开机时 | 补跑一次 |
| 每小时 | 最后一次保险（当天已签就 0 秒退出，不碰豆包） |

> 安装完 launchd 脚本之后再更改项目文件夹的位置 / 定时任务的时间（`schedule.*`），都要**重跑一次 `install-launchd.sh` 安装脚本**才会生效：原理是脚本会卸载当前 launchd 并按新的配置重装一次。

### 第 3 步（推荐）：在本机校准一次忙闲判断阈值

忙闲判断的作用是**避免在豆包客户端正在执行任务的时候把它重启了**。为此，脚本在动手前会观察 30 秒，看 CPU 和网络状态判断豆包客户端是不是正在干活。

阈值的出厂默认值来自开发机的校准，但每台电脑差别很大：**偏松会打断你，偏紧会漏签**。最好花两分钟在你本机调一次：

```bash
./scripts/doubao-checkin.sh --calibrate
```

校准是交互式的，会依次让你保持「空闲 / 正常聊天 / 跑个任务 / 任务刚结束」几种状态，最后给出建议阈值并问你要不要写回 `config.conf`。

## 其他日常使用命令

```bash
./scripts/doubao-checkin.sh --log          # 最近 20 次运行记录（最常用）
./scripts/doubao-checkin.sh --log=50       # 最近 50 次
./scripts/doubao-checkin.sh --doctor       # 环境诊断：进程、端口、CDP、缓存
```

这三条都**不会改动豆包**：`--log` 纯读文件，`--doctor` 只查进程和端口。

`--log` 的输出长这样：

```
时间             结果     耗时   端口  客户端   说明
──────────────────────────────────────────────────────────────────
2026-10-31 09:12 ALREADY  51.4s  9225  2.34.6   活动页面显示今日已签到，无需重复签到。
2026-10-31 08:58 BUSY     27.6s  -     2.34.6   客户端正在执行任务（网入中位 3.4KB/s > 3KB/s），本次跳过。
2026-10-31 08:41 SKIPPED  -      -     2.34.6   历史记录显示今日已签到（2026-10-31 08:12:30），本次跳过。
2026-10-31 08:03 SUCCESS  56.8s  9225  2.34.6   签到成功：每日签到 +200 额度

近 5 次：签到 1 · 已签 2 · 遇忙 1 · 其他跳过 1 · 失败 0
注意      遇忙跳过说明这次没签成；当天一直遇忙就是漏签，不是"已完成"
```

| 结果 | 含义 | 要不要管 |
|---|---|---|
| `SUCCESS` | 真的点了签到，领到额度 | 正常 |
| `ALREADY` | **打开页面**后才发现今天已经签过了 | 正常 |
| `BUSY` | 客户端正在跑任务，**这次没敢重启**，等下一轮 | 看一眼：当天最后一条还是 `BUSY` 就是漏签了 |
| `SKIPPED` | 这次直接跳过，什么都没做：大概率是因为脚本维护的历史记录显示今天已签到，也可能是前一次的签到脚本还没跑完 | 正常 |
| `PENDING` | `--dry-run` 看到按钮可点，但没点 | 正常，只有试运行会出现 |
| `FAIL` | 出错了，看「说明」列和 `checkin.log` | 要看 |
| `AUTH_FAIL` | 豆包登录态过期 | 重新登录一次即可 |
| `UNKNOWN` | 找不到签到卡片（活动下线或改版） | 不要反复重试 |

### 改了配置 / 想换时间 / 想停掉

| 想做的事 | 怎么做 |
|---|---|
| 改行为（是否允许重启、日志位置…） | 改 `config.conf`，**立即生效**，不用重装任务 |
| 改运行时间 / 登录补跑 / 兜底间隔 | 改 `config.conf` 的 `schedule.*`，**然后重装一次定时任务** |
| 改项目文件夹位置 | 把项目文件夹移动到新的位置，**然后重装一次定时任务** |
| 只删定时脚本 | `./scripts/install-launchd.sh --uninstall`，想用时再跑一次安装 |
| 彻底删除 | 先 `./scripts/install-launchd.sh --uninstall`，再删掉整个项目文件夹即可完美卸载，无残留 |

### 出问题时

| 现象 | 怎么办 |
|---|---|
| 弹出「登录态失效」 | 打开豆包重新登录，之后自动恢复 |
| 弹出「找不到签到卡片」 | 活动可能下线，或官方改版。看 `logs/checkin.log` 最后一段 |
| 完全没动静，`--log` 里也没有新记录 | 先 `--which-node`，再看 `logs/checkin.err` |
| 在豆包客户端执行任务的时候重启豆包 | 跑第 3 步校准；或手动把阈值调低 |
| 在豆包客户端空闲状态的时候拒绝签到 | 跑第 3 步校准；或手动把阈值调高 |
| 项目挪过位置之后不自动签到了 | 重跑一次 `./scripts/install-launchd.sh` |
| 豆包窗口白屏 / 点不动 / 发消息没反应 | 尝试用 `./scripts/doubao-checkin.sh --doctor` 诊断，或用 `--repair` 修复  |

需要贴日志求助时，`logs/checkin.log` 的最后一段就够（里面已经带了客户端版本）。

## 全部配置项

都在项目根目录的 **`config.conf`**，每一项都有注释说明默认值和影响。

| 设置 | 默认 | 说明 |
|---|---|---|
| `nodePath` | 空 | 指定用哪个 node。空 = 自动查找。填错会自动忽略并继续找 |
| `autoInstallNode` | `true` | 实在找不到 node 时，是否自动下载一份到 `vendor/` |
| `appPath` | `/Applications/Doubao.app` | 客户端路径，装在别处才需要改 |
| `cdpPort` | `9225` | 调试端口**起点**，被占用会自动往后找 |
| `logDir` | 空 | 日志目录，空 = 项目下的 `logs/`。必须是绝对路径 |
| `allowRelaunch` | `true` | 是否允许重启「开着但没调试端口」的豆包 |
| `busyCheck.enabled` | `true` | 重启前先判断你在不在用 |
| `busyCheck.windowSeconds` | `30` | 观察窗口（秒），越长越稳但要多等 |
| `busyCheck.sampleSeconds` | `3` | 采样间隔（秒），不建议低于 2 |
| `busyCheck.cpuThreshold` | `0.35` | 判定为忙的 CPU 阈值（核）。**建议在本机校准**（第 3 步） |
| `busyCheck.netInKBps` | `3` | 判定为忙的网络流入阈值（KB/s）。同上 |
| `schedule.times` | `03:33,13:33` | 每天跑的时刻，24 小时制、逗号分隔。**改完要重装定时任务** |
| `schedule.runAtLoad` | `true` | 登录 / 加载任务时补跑一次 |
| `schedule.intervalSeconds` | `3600` | 固定间隔兜底（秒），`0` = 关闭 |
| `breaker.threshold` | `3` | 连续失败几次后暂停自动重试，`0` = 不熔断 |
| `breaker.cooldownHours` | `12` | 熔断后隔多久放行一次试探 |
| `notify.debounceHours` | `6` | 同一类提醒多少小时内只弹一次，`0` = 每次都弹 |

写错了不会崩：文件不存在、只写一半、某项填错，都只是"那一项用默认值 + 打一条警告"，整个删掉也能工作。

**唯一的例外是 `schedule.*`**：它们由安装脚本读取并写进 plist，格式写错（比如 `25:00`、`7:5`）会让安装脚本直接中止——宁可装不上，也不要装上一个错的时间。

## 命令速查

| 用法 | 作用 |
|---|---|
| `./scripts/doubao-checkin.sh` | 立刻签一次 |
| `./scripts/doubao-checkin.sh --dry-run` | 只看状态，不点按钮 |
| `./scripts/doubao-checkin.sh --log[=N]` | 看最近 N 次记录（默认 20） |
| `./scripts/doubao-checkin.sh --doctor` | 环境 + 客户端健康诊断 |
| `./scripts/doubao-checkin.sh --repair` | 客户端白屏/点不动时修复（先问你） |
| `./scripts/doubao-checkin.sh --calibrate` | 校准忙闲阈值（交互式） |
| `./scripts/doubao-checkin.sh --which-node` | 用和定时任务完全相同的逻辑找 node |
| `./scripts/doubao-checkin.sh --find-node` | 列出查找顺序和实际会用的那个（想固定用某一份时看它） |
| `./scripts/doubao-checkin.sh --create-config` | 生成一份默认的 `config.conf`（已存在则不动） |
| `./scripts/doubao-checkin.sh --help` | 全部参数和说明 |
| `./scripts/install-launchd.sh` | 安装 / 重装定时任务 |
| `./scripts/install-launchd.sh --status` | 看当前状态 |
| `./scripts/install-launchd.sh --uninstall` | 卸载 |

安装脚本还有 `--allow-relaunch=yes|no`（跳过那次询问，直接把值写进 `config.conf`）、`--run-now`、`--dry-run`（只打印 plist，不注册）等参数，`--help` 里有完整说明。
